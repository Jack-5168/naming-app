## 🎯 一、产品定位（精简后）

### 1.1 三大差异化支柱（聚焦版）

```
支柱 1：AI 动态测试引擎 — 10 题=30 题精度，2.5 分钟完成
支柱 2：人格进化报告 — 月度/年度变化追踪，AI 生成解读
支柱 3：双人合测 2.0 — 冲突预警 + 相处建议，不是废分数

砍掉：
❌ 多模态交互（图片/语音）— 用户认知负担重，信效度低
❌ 游戏化系统（探索地图/徽章/盲盒）— 偏离核心，资源稀释
❌ 人格匹配系统 — 冷启动无解，1 万 DAU 后再做
❌ 主题圈子 — 内容社区运营成本高，非核心需求
```

### 1.2 MVP 验证原则

**前 10-12 周只验证 3 个核心假设**：

| 假设 | 验证方式 | 成功标准 |
|------|---------|---------|
| 动态测试精度 > 传统测试 | A/B 测试（10 题 vs 30 题） | 用户满意度 > 4.5/5 |
| 进化报告驱动重测 | 30 天推送重测提醒 | 重测率 > 25% |
| 双人合测驱动传播 | 分享率追踪 | 分享率 > 30% |

**如果 3 个假设都不成立** → 重新思考产品定位

**如果 1-2 个成立** → 聚焦成立的功能，砍掉其他

## 🚀 二、核心功能（砍掉 50% 后）

### 2.1 AI 动态测试引擎（P0，核心壁垒）

#### 功能描述
根据用户答案实时调整下一题，10 题达到传统 30 题的精度。

#### 技术方案（简化版）
```
Phase 1（Week 1-12）：混合模式
├── 70% 固定题目（已标定的 MBTI 题库，约 200 题）
├── 30% 动态题目（根据答案选择）
└── 置信度 75-80%（明确标注，降低预期）

Phase 2（Week 13-20）：纯动态模式
├── 400 题标定题库（8 维度 × 5 梯度 × 10 题）
├── 贝叶斯自适应算法
└── 置信度 85%+

Phase 3（Week 21-28）：优化迭代
├── 基于 10000+ 用户数据重新标定
├── 反作弊检测（社会期许偏差识别）
└── 置信度 90%+
```

#### 用户流程
```
1. 进入测试 → 阅读说明（标注"10 题，约 2.5 分钟"）
2. 第 1 题（所有人相同，基础题）
3. 根据答案选择第 2 题 → 置信度实时更新
4. ...
5. 第 10 题 → 生成结果（标注置信度，如"85%"）
6. 免费预览核心结果 → 付费解锁完整解读
```

#### 界面元素
```
┌─────────────────────────────────┐
│  进度：▓▓▓▓▓░░░░░ 50% (5/10)    │
│  置信度：78% → 82% → 85%        │
├─────────────────────────────────┤
│                                 │
│  在社交场合中，你通常：           │
│                                 │
│  ○ 主动和陌生人交谈             │
│  ○ 等别人先和你说话             │
│  ○ 看情况而定                   │
│  ○ 不太确定                     │
│                                 │
├─────────────────────────────────┤
│  [← 上一题]          [下一题 →] │
└─────────────────────────────────┘
```

#### 业务规则
- 答题进度实时保存（防止退出丢失）
- 支持中途退出，7 天内可继续
- 每道题必填，不可跳过
- **置信度<70% 时，建议用户做"深度测试"（30 题传统版）**

### 2.4 成长任务系统（P1，简化版）

#### 功能描述
基于人格弱点的个性化挑战，**不是游戏化**，是真实成长。

#### 任务设计原则
```
✅ 真实可执行（不是"变得更自信"这种空话）
✅ 7 天内可完成（不是月度目标）
✅ 有明确完成标准（不是"试试看"）
✅ 完成后有复盘（AI 生成反馈）
```

#### 任务示例（INFJ）
```
任务 1：边界感建立
├── 挑战：本周拒绝 1 次不合理请求
├── 提示：可以说"我现在手头有事，晚点回复你"
├── 完成标准：记录拒绝的场景 + 感受
└── 复盘 AI："拒绝后感觉如何？对方反应如何？"

任务 2：直接表达
├── 挑战：直接说出 1 次需求（不要暗示）
├── 提示：可以说"我希望你..."而不是"你要是能...就好了"
├── 完成标准：记录表达的内容 + 对方反应
└── 复盘 AI："直接表达后，结果比你想象的好还是坏？"

任务 3：行动力提升
├── 挑战：今天完成 1 件拖延超过 3 天的事
├── 提示：设定 25 分钟番茄钟，只做这一件事
├── 完成标准：记录完成的事 + 用时
└── 复盘 AI："完成后感觉如何？是什么阻碍了你 earlier 开始？"
```

#### 业务规则
- 免费用户每月可接 3 个任务
- 付费用户无限任务
- 完成任务获得成长积分（可解锁付费测试）
- 连续完成 7 天 → 推送"成长小结"（AI 生成）

## 🧪 七、人工 MVP 验证（新增）

### 7.1 成长系统需求验证（2 周）

**目的**：用最低成本验证"人格成长"是不是真需求，而不是花 12 周开发后才发现是伪需求。

**方案**：
```
Week 1: 招募种子用户
├── 渠道：小红书/朋友圈/心理学社群
├── 目标：100 人（免费）
├── 要求：愿意完成 28 天成长挑战
└── 筛选：高意向用户（填写申请表）

Week 2-5: 人工成长营
├── 微信群运营
├── 每周发布 1 个成长任务（人工）
├── 用户打卡（群内/私聊）
├── 周末复盘（人工反馈）
└── 28 天后问卷调研

Week 6: 数据分析
├── 任务完成率（目标>50%）
├── 付费意愿调研（目标>20% 愿意付¥299）
├── 主动重测率（目标>30%）
└── 深度访谈（10 人）

决策点：
✅ 完成率>50% + 付费>20% → 投入开发自动化成长系统
❌ 完成率<30% 或付费<10% → 砍掉成长系统，回归测试工具定位
```

### 7.2 双人合测验证（2 周）

**目的**：验证"冲突预警 + 相处建议"是否真的驱动传播。

**方案**：
```
Week 1: 手动合测服务
├── 招募 50 对情侣/好友
├── 双方分别完成测试（人工发题）
├── 手动生成合测报告（Canva 设计模板）
└── 微信交付

Week 2: 数据追踪
├── 分享率（目标>40%）
├── 付费意愿（目标>30% 愿意付¥29）
├── NPS（目标>50）
└── 深度访谈（5 对）

决策点：
✅ 分享率>40% + 付费>30% → 优先开发双人合测
❌ 分享率<20% 或付费<15% → 延后开发
```

## ⚠️ 八、风险与应对（更新）

### 8.1 技术风险

| 风险 | 概率 | 影响 | 应对 |

| 双人合测使用率低 | 中 | 中 | 先手动验证，数据好再开发 |
| 30 天重测率低 | 高 | 高 | 优化推送文案 + 报告价值 |

### 8.3 商业风险

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|

## 📊 九、关键变更总结（v2.0 → v2.1）

### 功能变更

| 维度 | v2.0 | v2.1 | 变更原因 |
|------|------|------|---------|
| 动态测试 | 100 题 | **200 题固定 + 动态混合** | 题目库被低估，需 400 题标定 |
| 多模态 | 图片 + 情境 + 语音 | **仅情境模拟（Phase 3）** | 认知负担重，信效度低 |
| 游戏化 | 探索地图 + 徽章 + 盲盒 + 积分 | **仅成长任务** | 避免产品变"四不像" |
| 社交 | 匹配 + 圈子 + 双人合测 | **仅双人合测** | 冷启动无解 |
| 高客单 | 成长营¥299 + 咨询¥199 | **7 天挑战¥9.9（验证中）** | 价格断层大，需求未验证 |

### 指标变更

| 指标 | v2.0 | v2.1 | 变更原因 |
|------|------|------|---------|
| 付费转化率 | 12% | **8-10%** | 更符合行业基准 |
| 30 日留存 | 30% | **25%** | 现实预期 |
| 订阅续费率 | 60% | **20-25%** | 行业均值 |
| LTV（90 天） | ¥205.9 | **¥120-150** | 现实预期 |

### 周期变更

| Phase | v2.0 | v2.1 | 变更原因 |
|-------|------|------|---------|
| Phase 1 | 6 周 | **12 周** | 题目库 + 算法校准被低估 |
| Phase 2 | 6 周 | **8 周** | 成长系统需验证 |
| Phase 3 | 4 周 | **8 周** | 情境模拟 + 运营系统 |
| **总计** | **16 周** | **28 周** | 现实评估 |

### 人力变更

| 角色 | v2.0 | v2.1 | 变更原因 |
|------|------|------|---------|
| 后端开发 | 1 人 | **3 人** | 微服务架构 |
| 算法工程师 | 0 人 | **2 人** | 动态测试 + LLM 解读必需 |
| 心理学顾问 | 0 人 | **1 人（兼职）** | 题目信效度验证必需 |
| **总计** | **5-6 人** | **9 人** | |
