## 📋 执行摘要

### v2.1 → v2.2 核心变更（根据优先级深度检验）

| 维度 | v2.1 | v2.2（极简版） | 变更原因 |
|------|------|---------------|---------|
| **开发周期** | 24-28 周 | **12 周（MVP 上线）** | 先活下来，再活得好 |
| **团队规模** | 9 人 | **3-4 人** | 前 1 万用户不需要微服务 |
| **功能范围** | 动态测试 + 进化报告 + 双人合测 | **动态测试 + 付费 + 基础报告** | 砍掉所有非核心功能 |
| **验证策略** | 人工 MVP + 技术 MVP | **4 周人工 MVP → 8 周技术 MVP** | 先验证需求再开发 |
| **架构设计** | 微服务 | **单体架构** | 前 1 万用户查 SQL 比后台快 |

### 一句话定位（不变）

> **人格探索局不是另一个心理测试工具，而是一套帮你理解自己、理解他人、持续成长的完整系统。**

### 12 周生死线目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 测试完成率 | >75% | 低于这个说明体验有问题 |
| 付费转化率 | >5% | 低于这个说明价值主张有问题 |

**达到这三个指标 → 继续投入 Phase 2**

## 🚀 二、核心功能（12 周 MVP）

### 2.1 动态测试引擎（简化版）

#### 技术方案
```
Phase 1（Week 1-4）：
├── 200 题固定题库（MBTI 标定题）
├── 简单动态算法（70% 固定 +30% 动态）
├── 置信度 75-80%（内部使用，不展示）
└── 无置信度显示（避免用户困惑）

测试流程：
第 1-3 题：所有人相同（基础题）
第 4-10 题：根据答案选择（动态）
第 11-15 题：校准题（验证前面答案）

总题数：10-15 题
总时长：3-4 分钟
```

#### 用户流程
```
1. 进入测试 → 阅读说明（标注"约 3-4 分钟"）
2. 逐题作答（进度条显示）
3. 完成提交 → 生成结果
4. 免费预览核心结果
5. 付费解锁完整解读（¥29）
```

#### 界面设计
```
┌─────────────────────────────────┐
│  进度：▓▓▓▓▓▓░░░░ 50% (5/10)    │
├─────────────────────────────────┤
│                                 │
│  在社交场合中，你通常：           │
│                                 │
│  ○ 主动和陌生人交谈             │
│  ○ 等别人先和你说话             │
│  ○ 看情况而定                   │
│  ○ 不太确定                     │
│                                 │
├─────────────────────────────────┤
│  [← 上一题]          [下一题 →] │
└─────────────────────────────────┘
```

#### 业务规则
- 答题进度实时保存（防止退出丢失）
- 支持中途退出，7 天内可继续
- 每道题必填，不可跳过
- **不显示置信度**（内部质量监控用）

## 📅 四、开发计划（12 周生死线）

### 4.1 人工 MVP 验证（Week 1-4，与技术开发并行）

**目的**：用最低成本验证付费意愿，技术 MVP 上线时已有真实数据。

```
Week 1: 招募种子用户
├── 渠道：小红书/朋友圈/心理学社群
├── 目标：50 人（愿意付费测试）
├── 筛选：高意向用户
└── 话术："全新人格测试，限时¥9.9 体验"

Week 2-3: 人工测试服务
├── 发题：微信发送 20 道测试题
├── 答题：用户微信回复答案
├── 报告：Canva 设计模板 + 手动填写
└── 交付：微信发送 PDF 报告

Week 4: 数据分析
├── 付费转化率（目标>10%）
├── NPS（目标>40）
├── 分享率（目标>30%）
└── 深度访谈（10 人）

决策点：
✅ 付费>10% + NPS>40 → 继续技术 MVP 开发
⚠️ 付费 5-10% + NPS>30 → 优化后继续
❌ 付费<5% 或 NPS<30 → 重新思考定位
```

### 4.2 技术 MVP 开发（Week 1-12）

```
Week 1-4: 测试引擎 + 题库
├── 200 题固定题库建设

├── 答题进度保存逻辑

├── 付费解锁逻辑

Week 9-10: 测试 + 审核
├── 真机性能测试
```

| NPS<20 | 中 | 高 | 深度访谈用户，找核心问题 |

### 8.2 技术风险

| 服务器性能问题 | 低 | 低 | 前 1 万用户单体架构足够 |

## 💡 十一、核心原则

### 1. 上线比完美重要 100 倍

```
12 周内上线 → 有真实用户 → 有真实数据 → 决定下一步做什么
12 周内上不了线 → 完美主义 → 资源耗尽 → 项目死亡
```

### 2. 验证比开发重要 10 倍

```
4 周人工 MVP 验证 → 花 0 元开发，验证付费意愿
8 周技术 MVP 开发 → 有真实数据支撑决策
```

### 3. 聚焦比扩张重要 100 倍

```
12 周只做 3 件事：
1. 动态测试（更准更快）
2. 付费闭环（验证商业）
3. 基础报告（价值交付）

其他所有功能，等这 3 件事验证成功后再说
```

### 4. 数据比直觉重要 10 倍

```
4 个核心指标：
- 测试完成率 >75%
- 付费转化 >5%
- NPS >30
- 分享率 >20%

达标就继续，不达标就优化或砍掉
没有"我觉得"，只有"数据显示"
```
