## 一、语义化 HTML — 让机器读懂你的页面

### 1.1 为什么语义化重要？

语义化 HTML 是 SEO 和 A11y 的基石。搜索引擎爬虫和屏幕阅读器都依赖 HTML 语义来理解页面结构。

```html
<!-- ❌ 无语义 — 搜索引擎无法理解结构 -->
<div class="header">
  <div class="nav">
    <a href="/">首页</a>
    <a href="/about">关于</a>
  </div>
</div>
<div class="main">
  <div class="article">
    <div class="title">文章标题</div>
    <div class="content">文章内容...</div>
  </div>
  <div class="sidebar">
    <div class="widget">推荐内容</div>
  </div>
</div>
<div class="footer">版权信息</div>

<!-- ✅ 语义化 — 结构清晰，机器可读 -->
<header>
  <nav aria-label="主导航">
    <ul>
      <li><a href="/">首页</a></li>
      <li><a href="/about">关于</a></li>
    </ul>
  </nav>
</header>
<main>
  <article>
    <h1>文章标题</h1>
    <p>文章内容...</p>
  </article>
  <aside>
    <section aria-labelledby="rec-heading">
      <h2 id="rec-heading">推荐内容</h2>
    </section>
  </aside>
</main>
<footer>
  <p>&copy; 2026 版权信息</p>
</footer>
```

### 1.2 HTML5 语义元素速查

| 元素           | 用途           | SEO 权重 | A11y 角色              |
| -------------- | -------------- | -------- | ---------------------- |
| `<header>`     | 页面/区块头部  | 中       | banner                 |
| `<nav>`        | 导航链接组     | 高       | navigation (landmark)  |
| `<main>`       | 页面主要内容   | **最高** | main (landmark)        |
| `<article>`    | 独立内容单元   | 高       | article                |
| `<section>`    | 主题内容区块   | 中       | region (需 aria-label) |
| `<aside>`      | 侧边/附属内容  | 低       | complementary          |
| `<footer>`     | 页面/区块底部  | 低       | contentinfo            |
| `<figure>`     | 独立媒体内容   | 中       | figure                 |
| `<figcaption>` | figure 的标题  | 中       | —                      |
| `<time>`       | 时间/日期      | 中       | —                      |
| `<mark>`       | 高亮标记       | 低       | —                      |
| `<details>`    | 可折叠内容     | 中       | —                      |
| `<summary>`    | details 的标题 | 中       | —                      |

### 1.3 标题层级 — SEO 的核心

```html
<!-- ✅ 正确的标题层级 -->
<h1>页面唯一主标题（每页仅一个）</h1>
<h2>一级子标题</h2>
<h3>二级子标题</h3>
<h3>二级子标题</h3>
<h2>一级子标题</h2>
<h3>二级子标题</h3>

<!-- ❌ 常见错误 -->
<h1>主标题</h1>
<h3>跳级了！</h3>
<!-- 从 h1 跳到 h3 -->
<h1>又一个 h1！</h1>
<!-- 多个 h1 分散权重 -->
```

**规则:**

1. 每页**只有一个** `<h1>`
2. 标题层级**不跳级** (h1 → h2 → h3，不能 h1 → h3)
3. h1 包含**核心关键词**
4. 标题要有**信息密度**，不要只写"简介"

### 1.4 列表语义

```html
<!-- 导航用无序列表 -->
<nav aria-label="主导航">
  <ul>
    <li><a href="/">首页</a></li>
    <li><a href="/products">产品</a></li>
  </ul>
</nav>

<!-- 有序步骤用有序列表 -->
<ol>
  <li>第一步：注册账号</li>
  <li>第二步：完善资料</li>
  <li>第三步：开始使用</li>
</ol>

<!-- 定义列表：术语解释 -->
<dl>
  <dt>SEO</dt>
  <dd>搜索引擎优化（Search Engine Optimization）</dd>
  <dt>A11y</dt>
  <dd>无障碍（Accessibility，11 个字母）</dd>
</dl>
```

## 二、ARIA — 增强无障碍访问

### 2.1 ARIA 是什么？

ARIA (Accessible Rich Internet Applications) 是一组属性，用于增强 HTML 的可访问性。

**黄金法则: 能用原生 HTML 语义，就不用 ARIA。**

```
最佳: <button>点击</button>
次佳: <div role="button" tabindex="0">点击</div>
```

### 2.2 Landmark Roles — 页面区域导航

屏幕阅读器用户可以通过 Landmark 快速跳转到页面不同区域：

```html
<header role="banner">
  <!-- 或直接用 <header> -->
  <nav role="navigation">
    <!-- 或直接用 <nav> -->
    <main role="main">
      <!-- 或直接用 <main> -->
      <aside role="complementary">
        <!-- 或直接用 <aside> -->
        <footer role="contentinfo">
          <!-- 或直接用 <footer> -->

          <!-- 自定义 landmark（HTML5 没有对应元素时） -->
          <div role="search">...</div>
          <div role="form">...</div>
        </footer>
      </aside>
    </main>
  </nav>
</header>
```

**多个同类型 landmark 必须用 aria-label 区分:**

```html
<nav aria-label="主导航">...</nav>
<nav aria-label="页脚导航">...</nav>
<nav aria-label="面包屑导航">...</nav>
```

### 2.3 常见 ARIA 属性

```html
<!-- aria-label: 给元素添加屏幕阅读器可读的标签 -->
<button aria-label="关闭对话框">✕</button>
<a aria-label="在 Twitter 上关注我们" href="/twitter">
  <svg>...</svg>
  <!-- 图标按钮需要 aria-label -->
</a>

<!-- aria-labelledby: 用另一个元素的内容作为标签 -->
<h2 id="product-title">iPhone 16 Pro</h2>
<p aria-labelledby="product-title">价格: ¥7999</p>

<!-- aria-describedby: 引用描述性文本 -->
<input type="email" aria-describedby="email-help" />
<p id="email-help">请输入有效的邮箱地址</p>

<!-- aria-hidden: 隐藏装饰性内容（屏幕阅读器跳过） -->
<span aria-hidden="true">⭐</span>
<span class="sr-only">5 星好评</span>

<!-- aria-live: 动态内容更新通知 -->
<div aria-live="polite" aria-atomic="true">
  <!-- polite: 等用户空闲时播报 -->
  <!-- assertive: 立即播报 -->
  <p id="cart-count">购物车: 3 件商品</p>
</div>

<!-- aria-expanded: 可折叠区域状态 -->
<button aria-expanded="false" aria-controls="menu">菜单</button>
<ul id="menu" hidden>
  ...
</ul>

<!-- aria-selected: 选项卡/列表项选中状态 -->
<button role="tab" aria-selected="true">Tab 1</button>
<button role="tab" aria-selected="false">Tab 2</button>

<!-- aria-required: 必填字段 -->
<input type="text" aria-required="true" />

<!-- aria-invalid: 验证错误 -->
<input type="email" aria-invalid="true" aria-describedby="email-error" />
<span id="email-error" role="alert">邮箱格式不正确</span>

<!-- role="alert": 重要通知（自动播报） -->
<div role="alert">操作失败，请重试</div>
```

### 2.4 焦点管理

```html
<!-- tabindex 规则 -->
tabindex="0"
<!-- 按 DOM 顺序可聚焦 -->
tabindex="-1"
<!-- 程序化聚焦（JS focus()），Tab 键跳过 -->
tabindex>0
<!-- ❌ 永远不要用正数，破坏自然 Tab 顺序 -->

<!-- 焦点陷阱（模态框场景） -->
<div role="dialog" aria-modal="true">
  <!-- Tab 键在模态框内循环，不会跑到背景 -->
  <button>确认</button>
  <button>取消</button>
</div>

<!-- 跳过导航链接（A11y 标配） -->
<a href="#main-content" class="skip-link"> 跳转到主要内容 </a>
<!-- 配合 CSS: .skip-link { position: absolute; left: -999px; }
     .skip-link:focus { left: 0; } -->
```

## 三、图片无障碍

### 3.1 alt 属性策略

```html
<!-- 信息性图片：alt 描述图片内容 -->
<img src="chart-2026.png" alt="2026年Q1营收增长35%，Q2增长28%" />

<!-- 装饰性图片：alt="" 空字符串（屏幕阅读器跳过） -->
<img src="divider.png" alt="" role="presentation" />

<!-- 功能图片：alt 描述功能而非外观 -->
<img src="print-icon.png" alt="打印页面" />
<!-- 而非 "打印机图标" -->

<!-- 复杂图片：用 longdesc 或 figure + figcaption -->
<figure>
  <img src="architecture-diagram.png" alt="系统架构图" />
  <figcaption>
    系统采用微服务架构，前端通过 API Gateway 与 User/Order/Payment 服务通信
  </figcaption>
</figure>

<!-- CSS 背景图：不需要 alt（装饰性） -->
<div class="hero" style="background-image: url(hero.jpg)"></div>
```

### 3.2 图片 SEO

```html
<!-- ✅ SEO 友好的图片 -->
<img
  src="/images/iphone-16-pro-blue-2560.webp"
  srcset="
    /images/iphone-16-pro-blue-640.webp   640w,
    /images/iphone-16-pro-blue-1280.webp 1280w,
    /images/iphone-16-pro-blue-2560.webp 2560w
  "
  sizes="(max-width: 768px) 100vw, (max-width: 1200px) 50vw, 33vw"
  alt="iPhone 16 Pro 蓝色 256GB 正面视图"
  width="1200"
  height="800"
  loading="lazy"
  decoding="async"
/>

<!-- 关键点: -->
<!-- 1. 文件名包含关键词 (iphone-16-pro-blue) -->
<!-- 2. alt 描述准确且包含关键词 -->
<!-- 3. srcset/sizes 响应式图片 -->
<!-- 4. width/height 防止 CLS -->
<!-- 5. loading="lazy" 延迟加载 -->
<!-- 6. WebP/AVIF 现代格式 -->
```

## 四、结构化数据 (Structured Data)

### 4.1 为什么需要结构化数据？

结构化数据帮助搜索引擎理解页面内容，从而展示**富媒体搜索结果** (Rich Results):

- ⭐ 星级评分
- 📊 价格信息
- 📅 活动信息
- 🍞 面包屑导航
- 📝 FAQ 折叠
- 💼 职位信息

### 4.2 JSON-LD 格式（推荐）

```html
<!-- 放在 <head> 或 <body> 中 -->
<script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "WebPage",
    "name": "页面标题",
    "description": "页面描述",
    "url": "https://example.com/page"
  }
</script>
```

## 五、页面 SEO 核心要素

### 5.1 `<head>` 完整模板

```html
<head>
```

### 5.2 SEO 标题与描述最佳实践

```
标题公式:
核心关键词 | 次要关键词 - 品牌名
或:
页面主题 - 品牌名 | 补充说明

示例:
✅ "SEO 优化指南 2026 — 完整教程 - 技术博客"
✅ "iPhone 16 Pro 购买指南 | 价格、配置、对比 - 数码评测"
❌ "首页"  (太泛)
❌ "欢迎来到我们的网站"  (浪费标题空间)

描述公式:
[行动号召] + [核心内容] + [差异化优势] + [关键词]

示例:
✅ "深入了解 2026 年前端技术趋势：SSR、AI 编程、Web Components。
     包含实战案例和性能对比，帮助开发者做出技术选型。"
❌ "这是一个关于前端技术的页面。"  (太泛，无信息量)
```

### 5.3 内部链接策略

```html
<!-- ✅ 好的锚文本 -->
<a href="/guide/seo-basics">SEO 基础入门指南</a>
<a href="/tools/lighthouse">Lighthouse 性能测试工具</a>

<!-- ❌ 差的锚文本 -->
<a href="/guide/seo-basics">点击这里</a>
<a href="/tools/lighthouse">了解更多</a>
```

### 5.4 页面速度对 SEO 的影响

Google Core Web Vitals 是排名因素：

| 指标               | 良好    | 需改进  | 差      |
| ------------------ | ------- | ------- | ------- |
| LCP (最大内容绘制) | ≤ 2.5s  | ≤ 4.0s  | > 4.0s  |
| INP (交互到下一帧) | ≤ 200ms | ≤ 500ms | > 500ms |
| CLS (累积布局偏移) | ≤ 0.1   | ≤ 0.25  | > 0.25  |

## 六、颜色对比度与可读性

### 6.1 WCAG 对比度标准

```
AA 级 (最低要求):
- 正常文本: 4.5:1
- 大号文本 (18px+ 或 14px+粗体): 3:1
- UI 组件: 3:1

AAA 级 (增强):
- 正常文本: 7:1
- 大号文本: 4.5:1
```

```css
/* ✅ 符合 WCAG AA 的颜色组合 */
:root {
  --text-primary: #1a1a1a; /* 在白色背景上 16.1:1 — AAA */
  --text-secondary: #4a4a4a; /* 在白色背景上 8.5:1 — AAA */
  --text-muted: #6b6b6b; /* 在白色背景上 4.6:1 — AA */
  --link-color: #0055cc; /* 在白色背景上 5.5:1 — AA */
  --error-color: #c00000; /* 在白色背景上 5.8:1 — AA */
  --success-color: #0a7c3a; /* 在白色背景上 4.6:1 — AA */
}

/* ❌ 对比度不足 */
.muted-text {
  color: #999;
} /* 3.95:1 — 不满足 AA */
.light-text {
  color: #ccc;
} /* 1.6:1 — 严重不足 */
```

### 6.2 不依赖颜色传达信息

```html
<!-- ❌ 只用颜色区分状态 -->
<span class="error">表单有错误</span>
<!-- 红色 -->
<span class="success">提交成功</span>
<!-- 绿色 -->

<!-- ✅ 颜色 + 图标 + 语义 -->
<div role="alert" class="error">
  <span aria-hidden="true">⚠️</span>
  <span>表单有 3 个错误，请检查后重试</span>
</div>
<div role="status" class="success">
  <span aria-hidden="true">✅</span>
  <span>提交成功</span>
</div>
```

## 十、关键要点总结

1. **语义化 HTML 是基础** — 搜索引擎和屏幕阅读器都依赖它
2. **ARIA 是增强** — 有原生语义就用原生，ARIA 补不足
3. **结构化数据带来富媒体结果** — 星级、价格、FAQ 直接展示在搜索结果中
4. **标题和描述是 SEO 门面** — 每页唯一，包含关键词，有吸引力
5. **可访问性不是附加功能** — 它是法律要求 (ADA/WCAG) 和商业需求
6. **Core Web Vitals 影响排名** — LCP/INP/CLS 必须达标
7. **颜色不是唯一信息通道** — 图标 + 文字 + 语义，三重保障
8. **表单是最容易出 A11y 问题的地方** — label、错误提示、焦点管理缺一不可
