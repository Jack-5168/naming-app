## 一、核心收获

### 1. 构建工具三层架构

构建工具不是黑盒，可以清晰分为三层：
- **用户配置层** — webpack.config.js / vite.config.js
- **核心引擎层** — Parser → Transformer → Generator → Graph → Optimizer → Emitter
- **扩展插件层** — Loaders / Plugins / Transformers / Resolvers

理解这个分层后，再看任何构建工具的源码都不会迷路。

### 2. Webpack 编译生命周期

关键 Hook 时序：`run → compile → make → buildModule → seal → optimize → emit → afterEmit → done`

其中 `make` 是构建模块的核心阶段，`seal` 是分块和优化阶段。写插件时选对 Hook 时机很重要。

### 3. Tapable 钩子系统

Tapable 是 Webpack 插件系统的基石，核心 Hook 类型：
- **SyncHook** — 简单同步触发
- **SyncBailHook** — 返回值拦截后续
- **SyncWaterfallHook** — 瀑布流传递
- **AsyncSeriesHook** — 异步串行
- **AsyncParallelHook** — 异步并行

手写 Tapable 后理解了 Webpack 插件为什么能精确控制执行时机。

### 4. Vite 开发服务器架构

Vite 快的核心原因：
- **按需转换** — 浏览器请求哪个模块才转换哪个，O(1) 启动
- **依赖预构建** — node_modules 用 esbuild 预构建为 ESM
- **原生 ESM** — 浏览器直接加载，不需要打包

与 Webpack 的根本区别：Webpack 是 O(n) 打包后发送，Vite 是 O(1) 按需转换。

### 5. Module Federation

Module Federation 解决了微前端的运行时集成问题：
- 每个 Remote 独立构建、独立部署
- 共享依赖通过版本协商避免重复加载
- 运行时动态加载，不需要构建时知道所有 Remote

核心 API：`container.init(sharedScope)` → `container.get('./export')`

### 6. 增量编译

- **Webpack 持久化缓存** — filesystem cache，配置文件变化时失效
- **Turbopack** — 节点级缓存（AST 级别），比文件级更精确
- **手写增量编译器** — 文件哈希对比，命中缓存则跳过

### 7. Rollup 库打包

库打包 vs 应用打包的选择：
- **应用** → Webpack/Vite（需要代码分割、HMR、动态 import）
- **库** → Rollup（需要多格式输出、Tree Shaking、干净输出）

关键配置：`exports` 字段、`sideEffects: false`、peerDependencies。

### 8. Rspack

Rust 编写的 Webpack 兼容构建器：
- 冷启动 8x 快，HMR 9x 快，生产构建 6x 快
- 兼容 Webpack Loader/Plugin 生态
- 使用 SWC 进行代码转换

## 二、关键代码理解

### 手写 Compiler 核心流程

```
Compiler.run()
  → hooks.initialize()
  → applyPlugins()
  → hooks.entryOption()
  → hooks.compile()
  → hooks.make() → buildModule(entry) → 递归构建依赖图
  → hooks.seal() → createChunks()
  → hooks.optimize()
  → generateAssets() → createBundle()
  → hooks.emit() → 写文件
  → hooks.afterEmit()
  → hooks.done()
```

### 手写 Vite 插件核心模式

```javascript
function myPlugin() {
  return {
    name: 'my-plugin',
    enforce: 'pre',  // 执行顺序
    config() {},     // 修改配置
    resolveId() {},  // 解析模块 ID
    load() {},       // 加载模块内容
    transform() {},  // 转换代码
    handleHotUpdate() {}, // HMR
  };
}
```

### 增量编译核心逻辑

```
1. 计算文件哈希 (MD5)
2. 对比缓存中的哈希
3. 未变化 → 使用缓存
4. 已变化 → 重新构建 → 更新缓存
```

| 架构 | 单工具理解 | 多工具对比 + 选型 |
