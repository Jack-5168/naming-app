## 一、模块打包的本质

### 为什么需要打包？

浏览器原生不支持 CommonJS/ESM 的混合使用（历史原因），且大量小文件请求性能差。打包工具的核心价值：

1. **模块解析** — 将 `import/require` 转换为浏览器可执行的代码
2. **依赖图构建** — 从入口出发，递归收集所有依赖
3. **代码转换** — TypeScript/JSX/Sass → 浏览器能跑的 JS/CSS
4. **优化** — Tree Shaking、代码分割、压缩、缓存策略

### 打包的核心流程

```
入口文件 → AST 解析 → 依赖图构建 → 代码转换 → 输出打包结果
```

## 二、手写简易 Bundler

### 2.1 最小可用版本（~100 行）

核心思路：从入口文件出发，递归解析 `import`/`require`，构建依赖图，最后合并输出。

```javascript
// mini-bundler.js
const fs = require('fs');
const path = require('path');
const { parse } = require('@babel/parser');
const traverse = require('@babel/traverse').default;
const { transformFromAstSync } = require('@babel/core');

// 1. 解析单个文件，提取依赖
function createModuleInfo(filePath) {
  const content = fs.readFileSync(filePath, 'utf-8');
  const ast = parse(content, {
    sourceType: 'module',
    plugins: ['jsx']
  });

  const dependencies = [];

  traverse(ast, {
    ImportDeclaration({ node }) {
      // 相对路径 → 绝对路径
      const depPath = path.join(path.dirname(filePath), node.source.value);
      dependencies.push(depPath);
    }
  });

  // 转换为浏览器可执行代码
  const { code } = transformFromAstSync(ast, null, {
    presets: ['@babel/preset-env']
  });

  return { filePath, dependencies, code };
}

// 2. 构建完整依赖图
function buildDependencyGraph(entryPath) {
  const entryModule = createModuleInfo(entryPath);
  const queue = [entryModule];
  const visited = new Set();
  visited.add(entryPath);

  for (const module of queue) {
    module.dependencies.forEach(depPath => {
      if (visited.has(depPath)) return;
      visited.add(depPath);
      const depModule = createModuleInfo(depPath);
      queue.push(depModule);
    });
  }

  return queue;
}

// 3. 生成打包输出
function bundle(entryPath) {
  const modules = buildDependencyGraph(entryPath);

  // 构建模块映射：相对路径 → { code }
  const moduleMap = {};
  modules.forEach(mod => {
    const key = './' + path.relative(process.cwd(), mod.filePath);
    moduleMap[key] = mod.code;
  });

  // 生成运行时包装代码
  return `
(function(moduleMap) {
  function require(modulePath) {
    // 相对路径解析
    function localRequire(relativePath) {
      return require(path.join(path.dirname(modulePath), relativePath));
    }
    
    const module = { exports: {} };
    const code = moduleMap[modulePath];
    if (!code) throw new Error('Module not found: ' + modulePath);
    
    // 执行模块代码
    (function(require, module, exports) {
      eval(code);
    })(localRequire, module, module.exports);
    
    return module.exports;
  }
  
  require('${Object.keys(moduleMap)[0]}');
})(${JSON.stringify(moduleMap)});
  `;
}

// 使用
const result = bundle('./src/index.js');
fs.writeFileSync('./dist/bundle.js', result);
console.log('✅ Bundled successfully!');
```

### 2.2 依赖图数据结构

```
依赖图 (Dependency Graph):
┌─────────────┐
│  index.js   │ ← 入口
└──────┬──────┘
       │
   ┌───┴───┐
   ▼       ▼
utils.js  app.js
   │       │
   ▼       ▼
constants.js  styles.css (被 loader 处理)
```

核心数据结构：
```javascript
// 每个模块节点
{
  id: 0,                    // 唯一 ID
  filePath: '/src/index.js', // 绝对路径
  relativePath: './src/index.js',
  dependencies: ['./utils.js', './app.js'], // 直接依赖
  code: '...',              // 转换后的代码
  assets: {},               // 静态资源
  chunks: []                // 所属 chunk
}
```

### 2.3 关键原理解析

**为什么需要 AST？**
- 正则解析 `import` 不可靠（字符串里的 import、注释里的 import）
- AST 能精确识别语法节点，区分 `import foo from 'bar'` 和 `// import foo from 'bar'`

**Babel 在打包中的角色：**
- `@babel/parser` — 源码 → AST
- `@babel/traverse` — 遍历 AST，收集依赖
- `@babel/core` + presets — AST → 转换后的代码

**模块包装模式（IIFE）：**
```javascript
// 每个模块被包装成：
(function(require, module, exports) {
  // 原始模块代码
  const utils = require('./utils.js');
  module.exports = { ... };
})(localRequire, module, module.exports);
```

### 3.3 Webpack 构建流程（生命周期）

```
1. 初始化参数        ← 合并配置
2. 创建 Compiler     ← 编译对象
3. 确定 Entry        ← 入口文件
4. 从 Entry 递归解析  ← 构建 Module Graph
   ├── 通过 Loaders 转换文件
   ├── 解析 import/require
   └── 递归处理依赖
5. 完成模块编译      ← 所有模块就绪
6. 输出 Chunk        ← 模块 → Chunk
7. 插件介入          ← Emit/AfterEmit 等 Hook
8. 写入文件系统      ← 输出文件
```

**关键 Hook 时序：**
```
environment → afterEnvironment
  → entryOption (确定入口)
  → compile (编译开始)
  → this-compilation
  → make (开始构建模块图)
  → build-module (构建单个模块)
  → seal (模块图完成，开始打包)
  → optimize (优化 chunks)
  → emit (输出前)
  → after-emit (输出后)
  → done (完成)
```

### 3.4 Tree Shaking 原理

```javascript
// math.js
export function add(a, b) { return a + b; }
export function multiply(a, b) { return a * b; }

// index.js
import { add } from './math.js';
console.log(add(1, 2));
// multiply 没有被使用 → Tree Shaking 移除
```

**Webpack 如何做到？**
1. ESM 是静态的（import 必须在顶层，不能条件 import）
2. Webpack 分析 AST，标记被使用的 export
3. 生产模式下，Terser 移除未使用的代码

**注意：** CommonJS (`require`) 无法 Tree Shaking，因为 `require` 是动态的。

## 四、Vite 深度解析

### 4.1 为什么 Vite 比 Webpack 快？

| 维度 | Webpack | Vite |
|------|---------|------|
| 开发启动 | 全量打包 | 无需打包，按需编译 |
| HMR | 重新打包变更模块 | 浏览器直接请求变更模块 |
| 生产构建 | Webpack | Rollup |
| 热更新速度 | 随项目增大变慢 | 恒定快 |
| 底层 | JavaScript | esbuild (Go) + Rollup |

**核心差异：**

```
Webpack 开发模式:
  入口 → 解析所有依赖 → 打包 → 启动 DevServer → 浏览器加载 bundle
  问题: 项目越大，打包越慢

Vite 开发模式:
  浏览器请求 index.html
    → Vite 拦截 <script type="module">
    → 实时转换 ESM import (按需编译)
    → 浏览器直接执行
  优势: 启动时间不随项目增大而变慢
```

### 4.2 Vite 开发服务器原理

```
浏览器请求: /src/main.js
       ↓
Vite DevServer 拦截
       ↓
1. 读取文件内容
2. 处理 ESM import 路径 (node_modules → /@modules/vue)
3. 通过 esbuild 转换 (TSX/JSX → JS)
4. 返回转换后的代码
       ↓
浏览器执行 (原生 ESM)
```

**关键代码（简化版）：**

```javascript
// Vite 开发服务器的核心逻辑
const vite = require('vite');

async function startDevServer() {
  const server = await vite.createServer({
    root: process.cwd(),
    server: { port: 3000 }
  });

  await server.listen();
  server.printUrls();

  // 中间件处理请求
  server.middlewares.use(async (req, res, next) => {
    // 1. 处理 .vue/.jsx/.ts 文件
    if (/\.(vue|jsx|tsx|ts)$/.test(req.url)) {
      const content = fs.readFileSync(req.url.slice(1), 'utf-8');
      const transformed = await server.transformRequest(req.url);
      res.end(transformed.code);
      return;
    }

    // 2. 处理 node_modules 导入
    if (req.url.startsWith('/@modules/')) {
      const pkg = req.url.replace('/@modules/', '');
      const resolved = require.resolve(`${pkg}/package.json`);
      const pkgJson = JSON.parse(fs.readFileSync(resolved, 'utf-8'));
      const entry = pkgJson.module || pkgJson.main;
      const filePath = path.join(path.dirname(resolved), entry);
      const content = await server.transformRequest(filePath);
      res.end(content.code);
      return;
    }

    next();
  });
}
```

### 4.4 Vite 的 esbuild 加速

```
esbuild (Go 编写) 的优势:
├── 并行处理 (Go goroutines)
├── 避免 JS/V8 开销
├── 内存高效 (共享字符串表)
├── 比 babel 快 10-100 倍
└── 用于: 依赖预构建、TS/JSX 转换、代码压缩

Webpack 的 babel-loader:
├── 串行处理
├── JS 单线程
├── 每个文件创建新进程
└── 慢但生态成熟
```

## 五、Webpack vs Vite 对比总结

### 5.1 架构对比

```
Webpack 架构:
┌─────────────────────────────────────┐
│         Webpack Compiler            │
│  Entry → Loaders → Plugins → Output │
│         (全量打包)                   │
└─────────────────────────────────────┘

Vite 架构:
┌──────────────┐     ┌───────────────┐
│  开发模式     │     │  生产模式      │
│  esbuild     │     │  Rollup       │
│  (按需编译)   │     │  (全量打包)    │
└──────────────┘     └───────────────┘
```

### 5.2 选择建议

| 场景 | 推荐 | 理由 |
|------|------|------|
| 新项目 | Vite | 启动快、HMR 快、配置简单 |
| 大型复杂项目 | Webpack | 插件生态成熟、灵活度极高 |
| 需要 SSR | 看框架 | Next.js → Webpack, Nuxt → Vite |
| 需要精细控制 | Webpack | 生命周期 Hook 丰富 |
| 简单项目/原型 | Vite | 零配置即可用 |

### 5.3 核心原理对照表

| 能力 | Webpack | Vite |
|------|---------|------|
| 模块解析 | 依赖图递归 | 浏览器原生 ESM |
| 代码转换 | babel-loader | esbuild (Go) |
| HMR | 重新打包变更模块 | 浏览器直接请求变更文件 |
| 代码分割 | splitChunks | manualChunks (Rollup) |
| Tree Shaking | 静态分析 ESM | 静态分析 ESM |
| 资源处理 | file-loader/url-loader | 内置 asset 模块 |
| CSS 处理 | style-loader/css-loader | 内置 CSS 处理 |

### 6.2 完整打包器实现

```javascript
// bundler.js — 完整的简易打包器
const fs = require('fs');
const path = require('path');
const babelParser = require('@babel/parser');
const traverse = require('@babel/traverse').default;
const babel = require('@babel/core');

class Bundler {
  constructor(options = {}) {
    this.entry = options.entry || './src/index.js';
    this.output = options.output || './dist/bundle.js';
    this.basedir = process.cwd();
    this.modules = [];
    this.moduleId = 0;
  }

  // 生成唯一模块 ID
  nextId() {
    return this.moduleId++;
  }

  // 解析单个文件
  parseModule(filePath) {
    const id = this.nextId();
    const relativePath = path.relative(this.basedir, filePath);
    const content = fs.readFileSync(filePath, 'utf-8');

    // 处理不同文件类型
    if (filePath.endsWith('.css')) {
      return {
        id,
        filePath,
        relativePath,
        dependencies: [],
        code: `
          const style = document.createElement('style');
          style.textContent = ${JSON.stringify(content)};
          document.head.appendChild(style);
          module.exports = {};
        `,
        isCSS: true
      };
    }

    // 解析 JS/JSX
    const ast = babelParser.parse(content, {
      sourceType: 'module',
      plugins: ['jsx', 'typescript']
    });

    const dependencies = [];

    traverse(ast, {
      ImportDeclaration({ node }) {
        const source = node.source.value;
        const dir = path.dirname(filePath);
        let resolved = path.resolve(dir, source);

        // 自动添加扩展名
        if (!fs.existsSync(resolved)) {
          for (const ext of ['.js', '.jsx', '.ts', '.tsx', '.css']) {
            if (fs.existsSync(resolved + ext)) {
              resolved = resolved + ext;
              break;
            }
          }
        }

        dependencies.push(resolved);
      }
    });

    // 转换代码
    const { code } = babel.transformFromAstSync(ast, null, {
      presets: ['@babel/preset-env', '@babel/preset-react'],
      filename: filePath
    });

    return { id, filePath, relativePath, dependencies, code };
  }

  // 构建依赖图 (BFS)
  buildGraph() {
    const entryModule = this.parseModule(
      path.resolve(this.basedir, this.entry)
    );
    this.modules.push(entryModule);

    const queue = [entryModule];

    while (queue.length > 0) {
      const current = queue.shift();

      for (const depPath of current.dependencies) {
        // 跳过 node_modules (实际项目中需要处理)
        if (depPath.includes('node_modules')) continue;

        const exists = this.modules.find(m => m.filePath === depPath);
        if (exists) continue;

        const depModule = this.parseModule(depPath);
        this.modules.push(depModule);
        queue.push(depModule);
      }
    }

    return this.modules;
  }

  // 生成打包代码
  generate() {
    const moduleMap = {};

    this.modules.forEach(mod => {
      const key = './' + path.relative(this.basedir, mod.filePath);
      moduleMap[key] = {
        id: mod.id,
        deps: mod.dependencies.reduce((acc, dep) => {
          const relPath = './' + path.relative(this.basedir, dep);
          const depModule = this.modules.find(m => m.filePath === dep);
          acc[relPath] = depModule ? depModule.id : null;
          return acc;
        }, {}),
        code: mod.code
      };
    });

    return `
(function(moduleMap) {
  var installedModules = {};

  function __require__(moduleId) {
    if (installedModules[moduleId]) {
      return installedModules[moduleId].exports;
    }

    var module = installedModules[moduleId] = {
      exports: {},
      id: moduleId,
      loaded: false
    };

    var moduleDef = moduleMap[moduleId];
    if (!moduleDef) {
      throw new Error('Cannot find module: ' + moduleId);
    }

    moduleDef.code.call(
      module.exports,
      function (depId) {
        var resolvedId = moduleDef.deps[depId];
        return __require__(resolvedId);
      },
      module,
      module.exports
    );

    module.loaded = true;
    return module.exports;
  }

  // 执行入口模块
  return __require__('${Object.keys(moduleMap)[0]}');
})(${JSON.stringify(moduleMap)});
    `.trim();
  }

  // 执行打包
  bundle() {
    console.log(`🔨 Building from: ${this.entry}`);

    const modules = this.buildGraph();
    console.log(`📦 Found ${modules.length} modules`);

    const output = this.generate();

    const outDir = path.dirname(path.resolve(this.basedir, this.output));
    if (!fs.existsSync(outDir)) {
      fs.mkdirSync(outDir, { recursive: true });
    }

    fs.writeFileSync(
      path.resolve(this.basedir, this.output),
      output
    );

    const size = (Buffer.byteLength(output) / 1024).toFixed(2);
    console.log(`✅ Bundle written to: ${this.output} (${size}KB)`);

    return output;
  }
}

// 使用
const bundler = new Bundler({
  entry: './src/index.js',
  output: './dist/bundle.js'
});

bundler.bundle();
```

## 八、总结

### 核心知识点

1. **打包的本质** = 模块解析 + 依赖图构建 + 代码转换 + 输出
2. **手写 Bundler** 理解了 AST、依赖图、模块包装、运行时
3. **Webpack** 是配置驱动的全量打包器，生态最成熟
4. **Vite** 利用浏览器原生 ESM 实现按需编译，开发体验极佳
5. **esbuild** (Go) 比 Babel (JS) 快 10-100 倍，是 Vite 快的核心原因
6. **Tree Shaking** 依赖 ESM 的静态分析，CommonJS 不支持
7. **代码分割** 是大型项目性能优化的关键手段
8. **构建优化** = 缓存 + 并行 + 缩小范围 + 预编译
