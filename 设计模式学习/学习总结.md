# 设计模式学习总结

## 📚 学习概览

本次专项训练学习了两个经典的 JavaScript 设计模式：

1. **单例模式 (Singleton Pattern)**
2. **观察者模式 (Observer Pattern)**

---

## 🎯 单例模式 (Singleton)

### 核心概念

确保一个类**只有一个实例**，并提供**全局访问点**来获取该实例。

### 关键特点

| 特点 | 说明 |
|------|------|
| 唯一实例 | 整个应用生命周期内只有一个实例 |
| 全局访问 | 通过统一接口获取实例 |
| 延迟加载 | 可以按需创建实例 |
| 状态共享 | 所有使用者共享同一状态 |

### 实现方式

1. **闭包实现** - 利用函数作用域隐藏实例
2. **ES6 Class** - 使用静态属性存储实例
3. **惰性初始化** - 首次使用时才创建
4. **线程安全** - 处理并发访问

### 适用场景

✅ **推荐使用**
- 配置管理器
- 日志记录器
- 数据库连接池
- 缓存系统
- 全局状态管理

❌ **避免使用**
- 需要多个实例的场景
- 单元测试密集的代码
- 可能导致全局状态污染的场景

### 代码示例

```javascript
// 配置管理器单例
class ConfigManager {
  constructor() {
    if (ConfigManager.instance) {
      return ConfigManager.instance;
    }
    this.config = { app: { name: 'MyApp' } };
    ConfigManager.instance = this;
  }
  
  get(path) { /* ... */ }
  set(path, value) { /* ... */ }
}

const config1 = new ConfigManager();
const config2 = new ConfigManager();
console.log(config1 === config2); // true
```

### 优缺点

**优点:**
- ✅ 内存开销小
- ✅ 避免资源重复占用
- ✅ 全局访问方便

**缺点:**
- ❌ 违反单一职责原则
- ❌ 可能导致全局状态污染
- ❌ 不利于单元测试
- ❌ 多线程需特殊处理

## 🔔 观察者模式 (Observer)

### 核心概念

定义**一对多的依赖关系**，当一个对象（主题）状态变化时，所有依赖它的对象（观察者）都会收到通知并自动更新。

### 关键特点

| 特点 | 说明 |
|------|------|
| 解耦 | 主题和观察者互相独立 |
| 广播 | 支持一对多通知 |
| 动态 | 运行时可添加/移除观察者 |
| 异步 | 支持同步/异步通知 |

### 实现方式

1. **基础观察者** - Subject + Observer 类
2. **事件总线** - 支持多事件类型
3. **优先级** - 按优先级顺序通知
4. **异步通知** - Promise 支持

### 适用场景

✅ **推荐使用**
- 事件处理系统
- 发布 - 订阅系统
- MVC 架构模型 - 视图同步
- 响应式编程
- 实时数据更新

❌ **避免使用**
- 观察者过多影响性能
- 存在循环依赖风险
- 需要严格顺序执行的场景

### 代码示例

```javascript
// 事件总线
class EventBus {
  constructor() {
    this.events = {};
  }
  
  on(event, callback) {
    if (!this.events[event]) this.events[event] = [];
    this.events[event].push(callback);
  }
  
  emit(event, data) {
    this.events[event]?.forEach(cb => cb(data));
  }
}

const bus = new EventBus();
bus.on('user:login', user => console.log(`Welcome ${user.name}`));
bus.emit('user:login', { name: 'Alice' });
```

### 优缺点

**优点:**
- ✅ 解耦主题和观察者
- ✅ 支持广播通信
- ✅ 符合开闭原则
- ✅ 支持连锁反应

**缺点:**
- ❌ 可能导致循环依赖
- ❌ 观察者过多性能问题
- ❌ 内存泄漏风险
- ❌ 不清楚变化来源

## 📊 两种模式对比

| 维度 | 单例模式 | 观察者模式 |
|------|----------|------------|
| **目的** | 控制实例数量 | 实现对象间通信 |
| **关系** | 无依赖关系 | 一对多依赖 |
| **耦合度** | 低 | 中等 |
| **复杂度** | 简单 | 中等 |
| **使用频率** | 高 | 非常高 |

## 💡 实战经验

### 单例模式注意事项

1. **测试困难** - 全局状态导致测试互相影响
   ```javascript
   // 解决方案：提供重置方法
   ConfigManager.reset = () => { ConfigManager.instance = null; };
   ```

2. **并发安全** - 多线程环境需要锁机制
   ```javascript
   async setData(key, value) {
     while (this.locked) await sleep(10);
     this.locked = true;
     // ... 操作
     this.locked = false;
   }
   ```

3. **避免滥用** - 不是所有类都需要单例

### 观察者模式注意事项

1. **内存泄漏** - 务必取消订阅
   ```javascript
   const unsubscribe = subject.subscribe(observer);
   // 组件销毁时
   unsubscribe();
   ```

2. **异常处理** - 单个观察者错误不影响其他
   ```javascript
   observers.forEach(obs => {
     try { obs.update(data); }
     catch (e) { console.error(e); }
   });
   ```

3. **性能优化** - 大量观察者时批量/异步通知
   ```javascript
   async notify(data) {
     await Promise.all(observers.map(o => o.update(data)));
   }
   ```
