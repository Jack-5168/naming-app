## 02:00 - 专项训练 02: 设计模式

学习了 2 个 JavaScript 设计模式：

### 1. 观察者模式 (Observer Pattern)

- **核心思想**: 定义对象间的一对多依赖，当一个对象状态改变时，所有依赖者都会收到通知
- **应用场景**: 事件系统、发布-订阅、数据绑定
- **实现要点**: Subject 维护观察者列表，notify 方法遍历通知

### 2. 策略模式 (Strategy Pattern)

- **核心思想**: 定义一系列算法，将每个算法封装起来，使它们可以互相替换
- **应用场景**: 表单验证、支付方式选择、排序算法切换
- **实现要点**: 策略接口统一，上下文类委托给具体策略执行

详细内容见 memory/design-patterns/ 目录。

| `README.md`         | 697  | 完整文档             |

### 覆盖的五大核心主题

**1. Fetch API 封装**

- `NetworkClient` 类：统一请求/响应接口
- 自动 JSON 序列化、Content-Type 智能判断
- 支持 GET/POST/PUT/DELETE/PATCH
- FormData 自动处理（上传场景）

**2. Axios 封装**

- `AxiosClient` 类：基于 `axios.create()` 的实例化客户端
- 自动 JSON 转换、HTTP 状态码检查
- 内置 CancelToken 取消支持

**3. 拦截器系统**

- `InterceptorManager`：请求/响应/错误三类拦截器链
- `createAuthInterceptor`：Token 自动注入
- `createLoggerInterceptor`：请求日志 + 耗时统计
- `createErrorInterceptor`：统一错误处理（401/403/500 分类）
- `createTokenRefreshInterceptor`：401 自动刷新 Token + 失败请求排队
- Axios 版本：`createAxiosAuthInterceptor` / `createAxiosLoggerInterceptor` / `createAxiosErrorInterceptor` / `createTokenRefreshInterceptor`

**4. 重试机制**

- `RetryManager`：指数退避策略（baseDelay × 2^(attempt-1)）
- 随机抖动（0-1000ms）避免雪崩
- 可配置：retryCount / retryDelay / shouldRetry 自定义条件
- 自动跳过取消请求和 4xx 客户端错误（429 除外）

**5. 请求取消**

- Fetch：`AbortController` + `signal` 机制
- Axios：`CancelToken.source()` 机制
- `createCancelToken()` 便捷 API
- 组件卸载自动取消、搜索框取消上一个请求

### 额外能力

- **请求去重** (`RequestDeduper`)：基于 URL+Method+Params+Data 生成 key，防止重复提交
- **超时处理**：Fetch `withTimeout` / Axios 内置 timeout
- **请求队列** (`RequestQueue`)：限流并发控制
- **离线缓存** (`CacheManager`)：TTL 过期管理
- **请求监控** (`RequestMonitor`)：成功率/平均耗时统计
- **React Hooks**：`useFetch` / `useSearch`（防抖+取消）
- **Token 刷新队列**：401 时排队等待刷新，刷新后重发

### 代码亮点

- 双引擎架构（Fetch + Axios）可自由切换
- 完整 TypeScript 类型定义
- 模块化设计（拦截器/重试/去重/超时独立模块）
- 生产级质量（Token 刷新队列、指数退避、请求去重、缓存管理）
- 可直接用于生产环境
