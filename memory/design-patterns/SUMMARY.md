# 专项训练 02:00 - 设计模式学习总结

## 已学习模式

| 文件 | 模式 | 核心 | JS 原生体现 |
|------|------|------|-------------|
| `01-observer.md` | 观察者模式 | 一对多依赖，状态变化自动通知 | `addEventListener()` |
| `02-strategy.md` | 策略模式 | 封装可互换算法族，运行时切换 | `Array.sort(compareFn)` |
| `03-singleton.md` | 单例模式 | 全局唯一实例，惰性创建 | `window`、`document`、ES6 Module |
| `04-factory.md` | 工厂模式 | 封装对象创建逻辑，调用者无需关心细节 | `Array.from()`、`Object.create()` |
| `05-proxy.md` | 代理模式 | 控制对目标对象的访问，拦截操作 | `Proxy`、`Object.defineProperty`、事件委托 |
| `06-decorator.md` | 装饰器模式 | 动态添加功能，不改变原始结构 | 函数组合、HOC、Koa 中间件、ES2022 Decorator |
| `07-adapter.md` | 适配器模式 | 将不兼容的接口转换为期望接口 | `Promise.then`、`Array.from`、第三方 SDK 封装 |
| `08-template-method.md` | 模板方法模式 | 父类定义算法骨架，子类实现步骤 | Express 中间件、Jest 测试框架、构建工具 |
| `09-builder.md` | 建造者模式 | 链式调用逐步构建复杂对象 | URLSearchParams、Promise 链式、jQuery |
| `10-command.md` | 命令模式 | 将请求封装为对象，支持撤销/队列/宏 | Redux dispatch、setTimeout、DOM 事件 |

## 模式关系图

```
工厂模式 ──创建──→ 策略对象 / 单例对象
                        ↓
观察者模式 ──通知──→ 策略执行结果

代理模式 ──拦截──→ 任何对象（访问控制/缓存/校验）
装饰器模式 ──增强──→ 任何对象（日志/重试/缓存/权限）

适配器模式 ──转换──→ 不兼容接口（翻译官，统一 SDK/数据源）
模板方法 ──骨架──→ 算法流程（父类定义流程，子类实现步骤）

建造者模式 ──链式──→ 复杂对象（一步步搭建，build() 产出不可变对象）
命令模式 ──封装──→ 请求/动作（execute + undo，支持撤销/队列/宏命令）
```

## 十大模式对比

| 模式 | 关系 | 目的 | 何时用 |
|------|------|------|--------|
| 单例 | 唯一 | 全局唯一 | 配置/连接池/日志 |
| 工厂 | 创建 | 封装创建逻辑 | 多种对象类型 |
| 策略 | 行为 | 可互换算法 | 运行时切换行为 |
| 观察者 | 通知 | 一对多依赖 | 事件驱动/响应式 |
| 代理 | 控制 | 访问拦截 | 校验/缓存/只读/延迟 |
| 装饰 | 增强 | 功能叠加 | 日志/重试/中间件 |
| 适配器 | 转换 | 接口不兼容→统一 | 第三方 SDK/新旧 API/多数据源 |
| 模板方法 | 骨架 | 算法流程固定，步骤可变 | 数据处理/测试框架/构建工具 |
| 建造者 | 构建 | 链式构建复杂对象 | 多参数配置/SQL 查询/HTTP 请求 |
| 命令 | 请求 | 动作对象化，支持撤销/队列 | Undo/Redo/命令队列/宏命令 |

## 设计原则回顾
1. **开闭原则**: 对扩展开放，对修改关闭（策略/装饰器最佳体现）
2. **单一职责**: 每个类只做一件事
3. **依赖倒置**: 依赖抽象而非具体实现
4. **里氏替换**: 子类可以替换父类
5. **组合优于继承**: 装饰器是最佳实践
